## 运输保真问题

当前 `desktop/webbetahost/site.js` 从渲染后的 `innerText` 提取助手正文，
`page.js` 将其作为协议增量发送。Markdown 渲染可能移除 JSON 转义字符，
仅改成 `textContent` 不能恢复原文。

离线证明使用第二题的合成结果，构造合法的 127 字节协议；CommonMark 文本
投影后变成 119 字节，SHA-256 与现场接收的错误帧完全一致。协作线程另外
使用 ReactMarkdown 和原站点适配器做了 DOM 对照，得到同一结果。

这是“提取链能造成完全相同损坏”的直接证据，不是现场上游原文已经被读取
或确认正确的证明。此前把接收帧缺转义直接归因于模型过早，现已纠正。
JSON 答案、Windows 路径、正则和代码均可能受影响。
