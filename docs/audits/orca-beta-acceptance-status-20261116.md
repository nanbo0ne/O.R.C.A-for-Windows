## 本次发现并处理的问题

1. 工具已执行不代表网页已经收到结果。新增独立回传状态后可分清到底卡在哪一步；不会因为模型收费为零就重复执行写入。
2. 主 Agent 放宽后，浏览器子 Agent 仍存在旧的五分钟墙钟限制。改为每父回合三十分钟，并扣除真实审批等待；同时暂停网页模型的有效工作计时。取消、拒绝、调用方截止时间和三十动作上限仍生效。
3. 每份回执都会重载同一个网页聊天，增加延迟并导致 R5 导航超时。R6 只复用 URL、文档代次、就绪状态均符合的当前聊天；需导航时仅在尚未排队发送前最多尝试两次。发送前再次核对网页地址，不向错误聊天发送。
4. 打开已有浏览器任务面板时，前端误发手动选标签命令，撞上自己的任务占用锁。已改为显示现有标签，不自动夺取控制权，也不替用户批准访问。
5. 新会话首轮渲染仍带着上一会话的浏览器状态，导致 A→B 时用 A 的标签初始化 B。已把状态和所属会话一起保存；Modern/Classic 的真实 React 点击测试先复现再通过。
6. 原生回调把 Go 指针转成整数后再转回，触发严格指针检查。已保留明确的指针参数；测试仍核对 GC/栈扩展前后地址不变。另修复 SID 读取和 UIA 输出指针的逃逸边界。整机操控继续禁用，不因修复测试而启用。
