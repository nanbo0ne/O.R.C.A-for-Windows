# O.R.C.A. Desktop 3.0.13 Verification

## Scope and privacy

This release includes the local conversation/monitor round and the subsequent attachment and presentation fixes. Testing uses synthetic conversations, image bytes and documents in temporary workspaces. Personal conversations, model configuration, service logs and the workstation clipboard were not inspected. No production model requests or interactive native-window manipulation were performed.

## Defects and corrections

- Compaction now updates model context independently of the persisted display timeline. Existing visible messages and stable IDs survive compaction/save/reload, with an inline compaction marker. Missing historical content cannot be recreated. Old checkpoints cannot overwrite a newer context epoch.
- The opt-in work monitor is bounded and memory-only. It observes request fields, returned text, tool progress and child lifecycle. Sensitive-field filtering is best effort, not a promise to recognize arbitrary or split secrets. Unobserved server phases and missing reasoning token counts are not invented.
- Transcript following uses a near-bottom tolerance and stable anchors. Todo and the jump-down control have separate measured space. Guidance uses normal message rendering outside folded process details.
- The phase strip is read-only: 6px color surface when collapsed, 28px on hover/focus, a light-gray external frame, moving bold labels, narrow separators and at most three visible sectors. Stop/disconnection freeze movement; reduced motion is respected.
- The permission popup is 184px wide with 34px rows. Other menus and Classic's general layout are unchanged.
- A delayed native clipboard fallback and a late browser paste event previously each attached a representation of the same content. Both now share one paste operation; duplicates within that operation are compared by content. A later deliberate paste or file-picker selection stays independent. Tests include images, documents, same-name/different-content files and mixed batches.
- Guidance previously lost its structured images and displayed model-facing reference text. The controller now validates and snapshots attachments in the parent turn, stores separate display text, passes image bytes to a vision-capable model and updates the task image resolver for a text model. Reopening and cross-workspace forks preserve attachment references. Filesystem paths are not substituted for visible thumbnails.
- Guidance admission is sealed atomically at completion. A correlated receipt is returned on consumption, not just enqueueing; cancellation/error rejects unconsumed guidance and leaves the draft. A later turn cannot receive an earlier queued guide.

## Release gates

Local regression and guidance review passed. CI race checks, three-platform packaging and isolated Windows 3.0.12 upgrade must pass before publication. CI and artifact results will be recorded in the delivered `RELEASE-VERIFICATION.md` and a follow-up here, tied to the exact release commit.

The source ZIP is generated from that commit with Git blob comparison, excluding only the historical top-level `release/` binaries. It excludes personal state and untracked local audits. The previous local source ZIP is removed only after its replacement passes integrity checks; historical releases are not deleted.

Windows Authenticode and macOS notarization are not supplied by this release setup. Minisign authenticates updater payloads; it is not an operating-system publisher signature. No system-DPI or live-provider performance claim is made.
