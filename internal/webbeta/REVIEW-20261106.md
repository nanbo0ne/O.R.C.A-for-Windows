# Browser and WebBeta Backend Review

Initial code-review scope: browser task/run ownership and observation, beta browser storage/transfer
confinement, account model selection for the browser role, and WebBeta
completion/lifecycle fail-closed behavior. No native window, user browser data,
live model call, account login, or frontend edit was used in this review. One
initial failing preflight regression reached COM bootstrap but failed at window
lookup before WebView creation or navigation; the repaired regression verifies
`h.started == false`. Synthetic account tests use the existing actual Go
client fixture, a temporary isolated profile, fake HTTP transports, and only its
local OAuth callback socket. They perform zero credential or inference requests.

## Reproduced and Fixed

1. P1: a confirmed WebBeta page completion whose final state checkpoint failed
   left the account enabled and could dispatch the next queued request. Opening,
   ordinary send, and tool-format correction all had this boundary. Each now
   latches uncertainty, disables sending, pauses reserve preparation, and rejects
   pending jobs while still holding the engine lock and scheduler slot. Restored
   storage cannot authorize a replay; the last durable Inflight journal also
   blocks sends after restart. All three regression cases failed before the fix.
2. P1: browser owner closure between task admission and the first URL lookup
   removed the tab and caused a nil dereference. The lookup now checks the task's
   cancellation, ownership, profile lease, pause/shutdown state, and tab lifetime
   under the same lock. Owner closure/tab removal reproduced the panic; replaced
   lease, pause, and shutdown previously exposed the stale address.
3. P2: browser current/explicit-role account models present only in the active
   catalog failed disk-only resolution. Exact account references now pass through
   `readyAccountModel` before optional stored metadata is used. No fallback,
   bare-model account guessing, persisted config rewrite, credential acquisition,
   or capability probe is introduced by fresh model selection. The trusted
   account endpoint is retained. Stored thinking, effort, effort capabilities,
   defaults, and context metadata survive resolution; current-tab effort applies
   only when no explicit browser-role model is selected. Server capability
   denials remain enforced by the existing account provider. Both missing-disk
   cases failed before the fix.
4. P1: managed metadata/profile/snapshot paths could traverse a junction into
   another profile. Existing-prefix resolution alone proved insufficient on the
   Windows test runtime: `EvalSymlinks` returned the junction's lexical path for
   an uncreated child. The beta-only guard now checks every existing ancestor's
   Windows reparse attributes, as well as profile confinement and resolved paths,
   before metadata reads/writes, snapshot creation/cleanup, and native profile
   bootstrap (rechecked on the STA and before controller creation). Synthetic
   official sentinels remain unchanged, and rejected native creation never starts
   the host. Ordinary non-isolated host behavior is unchanged.
5. P2: upload reads/download destinations bypassed official-profile exclusions.
   Both desktop admission and native transfer validation now reuse the isolated
   profile's existing discovery exclusions plus reparse checks. Explicit ordinary
   external files remain allowed; no portable-workspace restriction was added.
